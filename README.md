# CompilerToWasm — Mini Compiler Lab

An educational, source-driven compiler for MiniLang. The browser app runs a lexer, panic-mode recursive-descent parser, AST semantic checks, three-address-code generator, constant folder/propagator, liveness-based interference graph and greedy graph-coloring allocator, pseudo-assembly generator, dynamic WebAssembly Text (WAT) emitter, and browser WebAssembly runtime.

## Run locally

Requirements: Node.js 18+ and npm.

```sh
npm install
npm run dev
```

Open the local Vite URL. Type or select an example, click **Compile**, then **Run WebAssembly**. `wabt` compiles the generated WAT text into a binary at runtime; `WebAssembly.instantiate` executes that binary in the browser. Printing is connected through the `env.print` import. Build for deployment with `npm run build`.

## MiniLang grammar (EBNF)

```text
Program      = { Statement } ;
Statement    = Declaration | Assignment | Print | If | While | Block ;
Declaration  = ("int" | "float"), Identifier, ["=", Expression], ";" ;
Assignment   = Identifier, "=", Expression, ";" ;
Print        = "print", "(", Expression, ")", ";" ;
If           = "if", "(", Condition, ")", Statement, ["else", Statement] ;
While        = "while", "(", Condition, ")", Statement ;
Block        = "{", { Statement }, "}" ;
Condition    = Expression, [RelOp, Expression] ;
Expression   = Term, { ("+" | "-"), Term } ;
Term         = Unary, { ("*" | "/" | "%"), Unary } ;
Unary        = ("-" | "!"), Unary | Primary ;
Primary      = Integer | Float | Identifier | "(", Expression, ")" ;
RelOp        = "<" | ">" | "<=" | ">=" | "==" | "!=" ;
```

`src/compiler.js` contains stage implementations and their data flow. `src/App.jsx` is the educational IDE; `src/style.css` supplies its layout. The scanner strips line and block comments, tracks line/column positions, and returns tokens dynamically. Parser errors synchronize at semicolon, right brace, or EOF, allowing later statements to be analyzed. Symbol-table addresses are simulated global slots.

## Syllabus alignment

| Practical | Concept | Project component |
|---|---|---|
| 1 | Lex/Flex | JavaScript lexer demonstrates regular-expression tokenization; it is not generated by Flex |
| 2 | Token stream | Dynamic MiniLang lexer, comments, operators, line/column lexical diagnostics |
| 3 | Symbol table | Declarations, type, simulated address, scope and line; duplicate detection |
| 4 | CFG + Lex/YACC | EBNF and recursive-descent parser produce AST; handwritten parser, not YACC-generated |
| 5 | Error recovery | Panic-mode synchronization on `;`, `}`, EOF |
| 6 | Semantic analysis | Undeclared names, redeclarations, type checks and assignment checks |
| 7 | Three-address code | Expression temporaries and control-flow labels/jumps |
| 8 | Assembly + getreg | Simplified register table and pseudo-assembly |
| 9 | Optimization | Constant folding and propagation over TAC |
| 10 | Graph coloring | Backward liveness, interference graph, greedy register coloring and spill labels |

This academic demonstration uses handwritten JavaScript implementations of Lex/YACC concepts. It does not claim to invoke Flex or Bison. Function declarations, nested lexical scopes, arrays, booleans as a declared type, and source maps are outside the current language subset.

## Examples and expected outcomes

The IDE provides ten dynamic examples: arithmetic, if/else, while, constant folding, undeclared use, redeclaration, syntax recovery, nested expressions, register pressure, and comments. Select a sample to load its source. Valid programs show every stage; invalid programs show diagnostics and stop code generation. For example, `total = 10 + 20 * 2; print(total);` folds to a value of `50`, while the while-loop example prints `1, 2, 3, 4` in the browser runtime.

## Known teaching-model limits

The grammar is intentionally small. Numeric runtime storage uses WebAssembly `f64` globals to keep the target compact; source-level types are still tracked and checked. Register allocation is an educational approximation over TAC liveness (the browser Wasm backend independently lowers the AST). Pseudo-assembly is illustrative and is not assembled. The `int` remainder operation is represented using signed integer conversion, so `%` is intended for integer-valued operands. `&&` and `||` are lexed for token demonstrations but not parsed as compound expressions. This stage separation is made visible to support discussion of compiler design trade-offs.
