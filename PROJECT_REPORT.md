## 1. Abstract

This academic project presents the design, theoretical formulation, and implementation of an end-to-end educational compiler for **MiniLang**—a custom imperative programming language supporting variable bindings, arithmetic/relational/logical expressions, structured conditionals (`if-else`), loops (`while`), and user-defined functions with parameters and recursion. The compiler targets the **W3C WebAssembly (Wasm)** binary instruction format, enabling zero-install, safe, near-native execution directly inside modern web browsers.

Unlike toy simulators that display canned outputs, this compiler implements a true, source-driven compiler pipeline where each downstream stage operates strictly upon the data structures generated by preceding stages:
1. Lexical analysis converts source characters into typed tokens with line/column coordinates.
2. A recursive-descent parser transforms tokens into a typed Abstract Syntax Tree (AST) while utilizing panic-mode recovery.
3. Multi-pass semantic analysis manages a scoped symbol table and validates declarations, types, and function arity.
4. An intermediate representation (IR) generator emits Three-Address Code (TAC) and Quadruples.
5. An optimization pass executes compile-time constant folding and forward constant propagation.
6. A register allocator performs backward liveness analysis and greedy graph coloring over an interference graph.
7. Code generation emits WebAssembly Text Format (WAT), which is assembled into Wasm bytecode and executed in the browser's WebAssembly virtual machine with host I/O binding.

An interactive web-based compiler IDE provides real-time inspection of every intermediate data structure, making compiler design principles observable and demonstrable.

## 2. Problem Statement

In conventional undergraduate compiler design curricula, students often study compiler stages (lexical analysis, LL/LR parsing, type checking, intermediate code generation, and machine code generation) as isolated homework exercises or separate command-line assignments. Consequently:
- Students struggle to visualize how high-level syntax trees lower into three-address code and target instructions.
- Target architectures studied (such as MIPS, x86, or simple hypothetical RISC machines) require heavy external simulators or emulators, making verification cumbersome.
- Errors in early stages often cause whole-program crashes without intuitive visual diagnostics.

There is a distinct need for a cohesive, inspectable, and browser-executable compiler pipeline that bridges formal language theory with a modern real-world execution target (WebAssembly).

## 3. Objectives

The primary objectives of this project are:
1. **Design a clean imperative language (MiniLang):** Specify an unambiguous Context-Free Grammar (CFG) in Extended Backus-Naur Form (EBNF) supporting variables, control flow, functions, recursion, and I/O.
2. **Implement Lexical Analysis:** Tokenize source code, reject illegal characters, strip single- and multi-line comments, and track source positions for diagnostics.
3. **Implement Syntax Analysis & AST Generation:** Construct a recursive-descent parser with operator precedence climbing and panic-mode error recovery.
4. **Implement Scoped Semantic Analysis:** Build a symbol table tracking lexical scopes (global and function-local), verify declaration-before-use, prevent duplicate declarations, and enforce function signatures.
5. **Generate Intermediate Representation (IR):** Lower ASTs into Three-Address Code (TAC) and textbook Quadruples `(op, arg1, arg2, result)`.
6. **Implement Machine-Independent Optimization:** Perform local constant folding, algebraic simplification, and forward constant propagation across basic blocks.
7. **Demonstrate Register Allocation:** Implement backward liveness analysis, construct variable interference graphs, and color graphs using $K$ physical registers with spill tracking.
8. **Generate & Execute WebAssembly:** Lower validated ASTs into WebAssembly Text (WAT), assemble to binary bytecode, instantiate via the browser's `WebAssembly.instantiate` API, and capture standard output.
9. **Build an Educational IDE:** Provide an interactive interface with multi-stage tabs for tokens, AST, symbol tables, IR, optimizations, registers, assembly, WAT, and terminal execution.

## 7. Compiler Phases Detailed

### 7.1 Lexical Analysis (Scanner)
The scanner iterates over the source character stream:
- **Regular Expressions:** Identifiers `[a-zA-Z_][a-zA-Z0-9_]*`, numbers `\d+(\.\d+)?`.
- **Keywords:** `let`, `int`, `float`, `fn`, `function`, `return`, `if`, `else`, `while`, `print`, `true`, `false`.
- **Comments:** Skips line comments `//...` and block comments `/*...*/`. Reports unterminated block comments as lexical errors.
- **Position Tracking:** Maintains a running `(line, column)` counter for precise error diagnostics.

### 7.2 Syntax Analysis (Parser)
The parser implements a recursive-descent strategy based on the formal grammar:
- Implements precedence climbing for binary expressions to guarantee correct operator associativity and precedence ($* > + > == > \&\& > ||$).
- Constructs an Abstract Syntax Tree (AST) representing statements and expressions without superfluous punctuation tokens.
- Employs **panic-mode error recovery**: upon encountering a syntax error, the parser records the error, synchronizes by advancing until a statement terminator (`;`, `}`, or EOF), and resumes parsing downstream statements.

### 7.3 Semantic Analysis & Symbol Table
- **Scope Hierarchy:** A tree of symbol scopes where child scopes (e.g. function bodies) delegate symbol resolution to parent scopes.
- **Symbol Records:** Stores `(name, kind, type, scope, line, address_slot, arity)`.
- **Diagnostic Rules:**
  - Reports undeclared variables when an identifier is used without a declaration in the current or ancestor scopes.
  - Rejects duplicate variable or function declarations within the same lexical scope.
  - Rejects calls to undefined functions or calling a variable as a function.
  - Verifies function call argument counts (arity matching).
  - Flags `return` statements outside function bodies.

### 7.4 Intermediate Code Generation (IR)
Lowers the hierarchical AST into linear Three-Address Code:
- Temporaries $t_1, t_2, \dots$ store intermediate evaluation results.
- Relational comparisons emit conditional jumps `if_false t1 goto L2`.
- Function declarations emit `func_begin <name>` and `func_end <name>`.
- Function calls emit `param <arg>` followed by `t = call <func>, <arity>`.
- Every instruction is mapped to textbook **Quadruples**: `(op, arg1, arg2, result)`.

### 7.5 Code Optimization
Applies local optimizations over straight-line basic blocks:
- **Constant Folding:** Detects operations whose operands are statically known numeric literals (e.g. `t1 = 10 + 20 * 2` becomes `t1 = 50`). Evaluates binary arithmetic, relational comparisons, and unary negation at compile time.
- **Constant Propagation:** Tracks constant bindings and replaces subsequent variable occurrences with their folded literals until the variable is reassigned or a branch/label occurs.

### 7.6 Register Allocation & Target Lowering
Demonstrates hardware register constraints:
- Performs backward liveness analysis to calculate live ranges for all temporaries and program variables.
- Constructs an **Interference Graph** where an edge $(u, v)$ signifies that variables $u$ and $v$ are live simultaneously.
- Applies greedy degree-ordered graph coloring to assign each node to one of $K = 4$ physical registers ($R_1, R_2, R_3, R_4$). Nodes exceeding chromatic capacity are marked as memory spills (`MEM[var]`).
- Emits illustrative pseudo-assembly (`MOV`, `ADD`, `CMP`, `JMP`, `CALL`).

### 7.7 WebAssembly Code Generation & Execution
- Traverses the AST and emits valid WebAssembly S-Expressions (`.wat`):
  - Top-level variables are declared as mutable WebAssembly globals `(global $x (mut f64) (f64.const 0))`.
  - User functions are emitted with typed parameters `(param $p f64)` and local variables `(local $l f64)`.
  - Structured control flow maps to native Wasm `(if (then ...) (else ...))` and `(block (loop (br_if 1 ...) ... (br 0)))`.
  - Built-in `print` maps to an imported host function `(import "env" "print" (func $print (param f64)))`.
- The browser compiles the emitted WAT to binary bytecode using WABT and executes it natively via `WebAssembly.instantiate()`.

## 8. Language Grammar (EBNF)

```text
Program             = { Declaration | FunctionDecl | Statement } EOF ;

Declaration         = ("let" | "int" | "float") IDENTIFIER ["=" Expression] ";" ;

FunctionDecl        = ("fn" | "function") IDENTIFIER "(" [ ParamList ] ")" BlockStatement ;
ParamList           = IDENTIFIER { "," IDENTIFIER } ;

Statement           = Declaration
                    | FunctionDecl
                    | AssignmentStmt
                    | ReturnStmt
                    | PrintStmt
                    | IfStmt
                    | WhileStmt
                    | BlockStatement
                    | ExprStmt ;

AssignmentStmt      = IDENTIFIER "=" Expression ";" ;
ReturnStmt          = "return" [ Expression ] ";" ;
PrintStmt           = "print" "(" Expression ")" ";" ;
IfStmt              = "if" "(" Expression ")" Statement [ "else" Statement ] ;
WhileStmt           = "while" "(" Expression ")" Statement ;
BlockStatement      = "{" { Statement } "}" ;
ExprStmt            = Expression ";" ;

Expression          = LogicalOr ;
LogicalOr           = LogicalAnd { "||" LogicalAnd } ;
LogicalAnd          = Equality { "&&" Equality } ;
Equality            = Relational { ("==" | "!=") Relational } ;
Relational          = Additive { ("<" | "<=" | ">" | ">=") Additive } ;
Additive            = Multiplicative { ("+" | "-") Multiplicative } ;
Multiplicative      = Unary { ("*" | "/" | "%") Unary } ;
Unary               = ("-" | "!") Unary | Primary ;
Primary             = INT_LITERAL
                    | FLOAT_LITERAL
                    | "true" | "false"
                    | FunctionCall
                    | IDENTIFIER
                    | "(" Expression ")" ;

FunctionCall        = IDENTIFIER "(" [ ArgList ] ")" ;
ArgList             = Expression { "," Expression } ;
```

## 9. Algorithms & Pseudocode

### 9.1 Lexical Analyzer Algorithm
```text
Algorithm: LEX_SOURCE(source)
Input: Source code string
Output: tokens list, errors list

i <- 0, line <- 1, col <- 1
while i < length(source) do
  c <- source[i]
  if c is whitespace: advance(); continue
  if c == '/' and source[i+1] == '/': skip_until_newline(); continue
  if c == '/' and source[i+1] == '*':
    skip_until_closing_comment()
    if unclosed: errors.add("Unterminated block comment")
    continue
  if c is digit:
    match longest numeric literal
    tokens.add(Token(NUMERIC, lexeme, line, col))
    continue
  if c is letter or '_':
    match longest identifier
    if lexeme in KEYWORDS: tokens.add(Token(KEYWORD, lexeme, line, col))
    else: tokens.add(Token(IDENTIFIER, lexeme, line, col))
    continue
  if c in multi-character operators (==, !=, <=, >=, &&, ||):
    tokens.add(Token(op, op, line, col)); advance(2); continue
  if c in single-character operators or delimiters:
    tokens.add(Token(c, c, line, col)); advance(1); continue
  errors.add(CompileError("Invalid character", line, col))
  advance(1)
tokens.add(Token(EOF, "EOF", line, col))
return tokens, errors
```

### 9.2 Recursive-Descent Parser Algorithm
```text
Algorithm: PARSE_EXPRESSION()
Input: Current token pointer
Output: AST Expression Node

Function EXPRESSION(): return LOGICAL_OR()

Function MULTIPLICATIVE():
  node <- UNARY()
  while current_token.type in ['*', '/', '%'] do
    op <- advance()
    right <- UNARY()
    node <- BinaryExpression(op, node, right)
  return node

Function PRIMARY():
  if current_token is NUMBER: return NumericLiteral(advance().value)
  if current_token is IDENTIFIER:
    id <- advance()
    if current_token == '(': return FunctionCall(id, parse_args())
    return Identifier(id.value)
  if current_token == '(':
    advance()
    expr <- EXPRESSION()
    consume(')')
    return expr
  raise SyntaxError("Unexpected token in primary expression")
```

### 9.3 Semantic Analyzer Algorithm
```text
Algorithm: ANALYZE_AST(ast)
Input: AST root node
Output: Symbol table, Semantic errors

global_scope <- new Scope("global")
current_scope <- global_scope

Function VISIT_STATEMENT(node):
  switch node.kind:
    case VariableDeclaration:
      if current_scope.has_local(node.name):
        report_error("Duplicate declaration of " + node.name)
      else:
        current_scope.define(Symbol(node.name, "var", node.type))
      if node.init: CHECK_EXPR(node.init)

    case FunctionDeclaration:
      if global_scope.has_local(node.name):
        report_error("Duplicate function " + node.name)
      else:
        global_scope.define(Symbol(node.name, "fn", arity=node.params.length))
      child_scope <- new Scope("fn:" + node.name, parent=current_scope)
      current_scope <- child_scope
      for p in node.params: current_scope.define(Symbol(p, "param"))
      VISIT_BODY(node.body)
      current_scope <- current_scope.parent

Function CHECK_EXPR(node):
  if node is Identifier:
    sym <- current_scope.resolve(node.name)
    if sym is null: report_error("Undeclared variable: " + node.name)
  if node is CallExpression:
    sym <- current_scope.resolve(node.callee)
    if sym is null: report_error("Undeclared function: " + node.callee)
    else if sym.arity != node.args.length: report_error("Arity mismatch")
```

### 9.4 Optimizer Algorithm (Constant Folding & Propagation)
```text
Algorithm: OPTIMIZE_TAC(tac_instructions)
Input: Array of linear TAC strings
Output: Array of optimized TAC strings

constants_map <- new Map()
optimized <- []

for line in tac_instructions do
  if line is label or branch:
    constants_map.clear()
    optimized.add(line)
    continue

  // Propagate known constants
  for (var, const_val) in constants_map do
    substitute var with const_val on RHS of line

  // Fold binary constants (e.g. t1 = 10 + 20)
  if line matches "dest = num1 op num2":
    result <- EVALUATE(num1, op, num2)
    constants_map.set(dest, result)
    optimized.add("dest = " + result)
    continue

  optimized.add(line)
return optimized
```

### 9.5 WebAssembly Code Generator Algorithm
```text
Algorithm: EMIT_WAT(ast)
Input: Validated AST
Output: WAT string

wat_globals <- declare_global_variables(ast)
wat_functions <- []
top_level_instructions <- []

for node in ast.body do
  if node is FunctionDeclaration:
    wat_functions.add(LOWER_FUNCTION(node))
  else:
    top_level_instructions.add(LOWER_STATEMENT(node))

return FormatModule(
  import_print(),
  wat_globals,
  wat_functions,
  export_run(top_level_instructions)
)
```

## 10. Comprehensive Test Cases & Evaluation

Below are 12 rigorous test cases executed against the compiler pipeline:

### Test Case 1: Basic Arithmetic & Operator Precedence
- **Input:**
  ```javascript
  let a = 10;
  let b = 20;
  let result = a + b * 2;
  print(result);
  ```
- **Compiler Behavior:** Lexer produces 18 tokens. Parser ensures `b * 2` is evaluated before addition. TAC generates temporaries `t1 = b * 2`, `t2 = a + t1`. Optimizer folds constants if known. WAT compiles and executes.
- **Expected Output:** `50`

### Test Case 2: Conditional Branching (`if-else`)
- **Input:**
  ```javascript
  let score = 85;
  if (score >= 90) {
    print(1);
  } else {
    if (score >= 75) {
      print(2);
    } else {
      print(3);
    }
  }
  ```
- **Compiler Behavior:** Evaluates `>=` comparison into boolean jump condition. Generates label branches `if_false ... goto L2`. Executes else branch and nested if.
- **Expected Output:** `2`

### Test Case 3: Loop Iteration (`while`)
- **Input:**
  ```javascript
  let count = 1;
  let sum = 0;
  while (count <= 5) {
    print(count);
    sum = sum + count;
    count = count + 1;
  }
  print(sum);
  ```
- **Compiler Behavior:** Loop header label `L1:`, conditional exit `if_false ... goto L3`, loop body, and backward jump `goto L1`. Wasm maps to `(block (loop (br_if 1 ...) ... (br 0)))`.
- **Expected Output:** `1`, `2`, `3`, `4`, `5`, `15`

### Test Case 4: User-Defined Functions & Return Values
- **Input:**
  ```javascript
  fn multiply(x, y) {
    let product = x * y;
    return product;
  }
  let a = 6;
  let b = 7;
  let res = multiply(a, b);
  print(res);
  ```
- **Compiler Behavior:** Symbol table registers function `multiply` with arity 2 and creates local scope `fn:multiply` for parameters `x, y` and local `product`. WAT emits `(func $multiply (param $x f64) (param $y f64) (result f64) ...)`. Top-level invokes `(call $multiply ...)`.
- **Expected Output:** `42`

### Test Case 5: Recursive Function (Factorial)
- **Input:**
  ```javascript
  fn factorial(n) {
    if (n <= 1) {
      return 1;
    }
    return n * factorial(n - 1);
  }
  let result = factorial(5);
  print(result);
  ```
- **Compiler Behavior:** Verifies recursive call `factorial(n - 1)`. WebAssembly handles recursive stack frames natively in browser V8 engine.
- **Expected Output:** `120`

### Test Case 6: Optimization (Constant Folding & Propagation)
- **Input:**
  ```javascript
  let folded = 10 + 20 * 2;
  let boolFold = 5 > 3;
  let total = folded + 10;
  print(total);
  ```
- **Compiler Behavior:** Optimizer evaluates `10 + 20 * 2` to `50` at compile time. Propagates `folded = 50` into `50 + 10` which folds to `60`.
- **Expected Output:** `60` (with optimizations recorded in optimizer log)

### Test Case 7: Compound Boolean Logic
- **Input:**
  ```javascript
  let x = 15;
  let y = 25;
  if (x > 10 && y < 30) {
    print(100);
  }
  if (!(x == 0)) {
    print(200);
  }
  ```
- **Compiler Behavior:** Parses `&&` and `!` with proper precedence. Wasm lowers logical AND via `i32.and` over comparison results.
- **Expected Output:** `100`, `200`

### Test Case 8: Modulo & Remainder Arithmetic
- **Input:**
  ```javascript
  let number = 29;
  let divisor = 5;
  let remainder = number % divisor;
  print(remainder);
  ```
- **Compiler Behavior:** Lowers `%` operator in WebAssembly using signed 64-bit integer conversion `i64.rem_s`.
- **Expected Output:** `4`

### Test Case 9: [Error] Undeclared Variable Detection
- **Input:**
  ```javascript
  let a = 10;
  let result = a + b;
  print(result);
  ```
- **Expected Compiler Phase:** Semantic Analysis.
- **Expected Error:** `Semantic Error: Variable 'b' is not declared in this scope.` (Line 2, Col 18). Stops code generation.

### Test Case 10: [Error] Duplicate Variable Declaration
- **Input:**
  ```javascript
  let x = 10;
  let x = 20;
  print(x);
  ```
- **Expected Compiler Phase:** Semantic Analysis.
- **Expected Error:** `Semantic Error: Duplicate variable declaration of 'x' in scope 'global'.` (Line 2, Col 5).

### Test Case 11: [Error] Function Arity Mismatch
- **Input:**
  ```javascript
  fn square(x) {
    return x * x;
  }
  let val = square(5, 10, 15);
  print(val);
  ```
- **Expected Compiler Phase:** Semantic Analysis.
- **Expected Error:** `Semantic Error: Function 'square' expects 1 argument(s), but got 3.` (Line 4, Col 11).

### Test Case 12: [Error] Syntax Error & Panic-Mode Recovery
- **Input:**
  ```javascript
  let a = 10

  ```
- **Expected Compiler Phase:** Syntax Analysis.
- **Expected Error:** `Syntax Error: Expected ';' after variable declaration.` (Line 2, Col 1). Panic recovery synchronizes at next statement, allowing subsequent tokens to be verified.
